# Progressive Examples

Examples are product demonstrations and benchmark inputs, not decorative screenshots.

The canonical public set uses five progressive levels with three complementary primary examples per level.

## Level 1 — Control one interaction

1. [Destructive Confirmation](level-1-destructive-confirmation/) — consequential action, safeguards, failure and recovery
2. [Inline Form Validation](level-1-inline-form-validation/) — validation timing, feedback, accessibility and state preservation
3. [Search and Filter](level-1-search-and-filter/) — visible state, reversible narrowing, empty/error states and context preservation

## Level 2 — Complete one user task

1. [Mobile Account Recovery](level-2-mobile-account-recovery/) — interruption, expiry, resend and recovery
2. [Guest Checkout](level-2-guest-checkout/) — transactional flow, informed choice and payment recovery
3. [API Permission Setup](level-2-api-permission-setup/) — technical configuration, validation, scope and recovery

## Level 3 — Design one feature

1. [AI-Assisted Support](level-3-ai-assisted-support/) — human-AI authority, source distinction and control
2. [SaaS Analytics](level-3-saas-analytics/) — IA, realistic data, hierarchy and responsive feature behaviour
3. [Reference-Driven Developer Portal](level-3-reference-driven-developer-portal/) — reference evidence, structural originality and design-system integration

## Level 4 — Design a coherent product area

1. [Operations Review Workspace](level-4-operations-review-workspace/) — dense operational work, shared state and bounded refinement
2. [Ecommerce Account Area](level-4-ecommerce-account-area/) — shared patterns, historical/editable data and multi-flow consistency
3. [Media Discovery and Playback](level-4-media-discovery-and-playback/) — discovery-to-playback continuity, entitlement and cross-flow state

## Level 5 — Research-to-validated redesign

1. [Interrupted Financial Decision](level-5-interrupted-financial-decision/) — complete evidence-to-handoff lifecycle
2. [Conflicting Evidence Redesign](level-5-conflicting-evidence-redesign/) — contradiction preservation and competing explanations
3. [Failed Interaction Hypothesis](level-5-failed-interaction-hypothesis/) — retained knowledge, root cause and bounded replacement strategy

## Example contract

Every primary example contains a complete copyable generation prompt and a primary benchmark focus.

When implemented with fixtures, each example should also contain realistic source material, expected properties, deliberate traps and an evaluation contract. Multiple valid UX solutions may pass when they satisfy the required invariants.

Supplementary examples and regression fixtures may be added outside the 15 primary examples when they cover materially different behaviour.
