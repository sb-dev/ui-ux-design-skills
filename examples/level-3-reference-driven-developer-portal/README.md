# Level 3 Reference-Driven Developer Portal

**Level:** 3  
**Product:** Developer portal  
**Status:** Scaffold definition

## Generation prompt

```text
Use uiux-design, uiux-evaluate and uiux-handoff to redesign a developer portal feature using supplied interface references without copying their structure blindly.

Context:
The portal helps developers inspect API usage, recent errors, credentials and documentation links. Several reference products are supplied for visual density, typography, navigation and code presentation.

Requirements:
- Treat supplied references as design evidence, not user evidence
- Record which characteristics are relevant and which are unsuitable
- Model the developer tasks independently of the reference layouts
- Generate at least two structurally different feature directions
- Reuse the existing product design system where appropriate
- Include realistic code, error and empty states
- Define responsive behaviour and accessibility
- Preserve product-specific terminology and information relationships

Workflow:
- Analyse the references by characteristic rather than brand imitation
- Build the task model and IA from product requirements
- Explore structural alternatives before visual direction
- Select the lowest useful fidelity for the unresolved question
- Evaluate task fit, hierarchy, reference influence, distinctiveness and preservation
- Produce an implementation-ready handoff

What to optimise for:
- contextual reference use
- developer efficiency
- coherent information hierarchy
- original structure
- design-system fit
```

## Primary benchmark focus

reference provenance; structural alternatives; non-copying; design-system integration; responsive feature coherence.
