# reference-driven-saas-product

Apply this pack when supplied interface references should inform a SaaS design without becoming copied task structure, information architecture or unsupported product evidence.

## Production profile

Prioritise:

- reference provenance and intended use;
- transferable versus unsuitable characteristics;
- product-specific task and data relationships;
- structural alternatives before visual convergence;
- design-system integration where appropriate;
- realistic content/data density;
- responsive behaviour;
- distinctiveness without arbitrary novelty.

## Core skill deltas

### `uiux-research`

Treat references as reference/design evidence rather than user evidence. Record what each reference is intended to inform and where applicability is uncertain.

### `uiux-design`

Model tasks independently of the references, generate structural alternatives and use reference characteristics only where context supports them.

### `uiux-evaluate`

Evaluate task fit, reference provenance, structural non-copying, hierarchy, distinctiveness, preservation and design-system consistency.

### `uiux-handoff`

Preserve product-specific behaviour and record design-system mappings or unresolved reference-derived decisions where material.

## Must remain stable

Core evidence provenance, accessibility, approval, fidelity selection, preservation, diagnosis and bounded-refinement rules remain authoritative.

## Precedence

Explicit project/user instructions and approved UX decisions outrank this pack.

## Boundaries

This pack does not grant permission to copy proprietary interfaces or treat competitor patterns as validated product requirements.
