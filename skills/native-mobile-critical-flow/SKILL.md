# native-mobile-critical-flow

Apply this pack when a native-mobile task must survive interruption, expiry, backgrounding, termination, permission boundaries or recoverable failure.

## Production profile

Prioritise:

- task continuity across app lifecycle changes;
- explicit resume and expiry behaviour;
- predictable navigation/back/cancel semantics;
- keyboard, focus and touch behaviour;
- permission requests at the point of need;
- offline, retry and failed-upload states;
- preservation of completed valid work;
- accessible mobile interaction and handoff.

## Core skill deltas

### `uiux-research`

Add lifecycle/interruption evidence questions only when relevant. Do not infer mobile conventions as user evidence.

### `uiux-design`

Make interruption, resume, permissions, input and native navigation first-class state concerns. Use executable mobile fidelity only when runtime behaviour is the unresolved uncertainty.

### `uiux-evaluate`

Evaluate continuity, recovery, navigation, input, permissions, accessibility and whether lifecycle handling preserves approved task semantics.

### `uiux-handoff`

Specify background/resume, expiry, navigation, input, permission, retry and persistence behaviour where material.

## Must remain stable

Core evidence provenance, accessibility, approval, fidelity selection, preservation, diagnosis and bounded-refinement rules remain authoritative.

## Precedence

Explicit project/user instructions and approved UX decisions outrank this pack.

## Boundaries

This pack does not implement native applications, navigation libraries, permissions APIs, Maestro or Appium.
