# UI/UX Extension Packs

Extension Packs add bounded specialised production rules to the four core skills. They do not replace the core lifecycle.

## Catalogue

### Product / interaction

- `mobile-native` — first-wave candidate
- `saas-dashboard`
- `developer-tools`
- `ecommerce`
- `content-media`
- `landing-page`

### Human science

- `cognitive-science`
- `human-factors`
- `behavioural-science`
- `trust-and-ai-interaction` — first-wave candidate
- `ux-measurement`

### Design specialisation

- `motion-design`
- `design-system`
- `reference-driven-design` — first-wave candidate
- `immersive-web`
- `conversion-design`

## Activation ownership

Persistent selection belongs to the consuming project or user.

- **Explicit**: use the requested pack.
- **Configured**: use packs already selected by the project.
- **Suggested**: recommend a relevant pack.
- **Temporary inference**: apply only to the current operation when relevance is unambiguous, disclose it, and do not persist it automatically.

## Implementation gate

Do not implement the first-wave packs until the core Level 5 workflow is proven. Each implemented pack must add production-rule deltas, specialised evaluation, a showcase and core-vs-core+pack benchmark evidence.
